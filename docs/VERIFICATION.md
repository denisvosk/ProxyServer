# Проверка Proxy Server 2.1

Этот отчёт разделяет сборку EXE, переносимые проверки и исполнение на Windows. Конкретная VDS пользователя и его клиентские подключения в стенд не входят.

## Новая версия

| Проверка | Фактический статус | Область проверки |
|---|---|---|
| C++11, строгая компиляция новых единиц Windows | PASS, предупреждения считаются ошибками | Окно, служба, IPC, хранение профиля, правила брандмауэра |
| Полная сборка Windows x64 и проверка PE | Отдельный отчёт `WINDOWS_BUILD.json` готового архива | Все производственные единицы, линковка, ресурсы, версия и импорты |
| Расчёт правил брандмауэра | **94 проверки PASS** | Программа + выбранные порты; UDP; IP; MTProto; отсутствие публичного DNS; некорректные пути |
| Кодек профиля и IPC | **1 078 проверок PASS** | Все поля, секреты, границы формата, повреждённые и усечённые сообщения |
| Windows SCM, DPAPI, ACL, настоящее окно и GOST | Подготовлен отдельный Windows CI; фактический запуск подтверждается журналом Actions | `tests/Run-ServiceTests.ps1`, `tests/service_integration_win.cpp` |

## Сборка

Сохранены C++11 и проект Visual Studio с выбором v140 для VS 2015. Ошибки C4996 от `wcsncpy` устранены ограниченным копированием; повторные определения `WIN32_LEAN_AND_MEAN` и `NOMINMAX` защищены. Файлы с русским текстом имеют UTF-8 BOM, строки UTF-8 для IPC помечены явно.

Для Linux → Windows восстановлены GCC 14.2 / MinGW-w64 12.0.0 из проверенных Debian-пакетов. На неизменённых исходниках 2.0 этим комплектом побайтово воспроизведён прежний EXE: SHA-256 `4c371ef2e987fa268e0b56d82ec764a99667874e7b65be5c21cec904236af232`. Это подтверждает воспроизводимость инструментов; версия 2.1 имеет собственную контрольную сумму.

Готовый EXE проверяется как AMD64 PE32+ GUI, с иконкой 101, версией 2.1.0.0, манифестом `requireAdministrator`, DPI, ASLR/NX/high entropy VA и системными импортами. Статический runtime исключает необходимость отдельных MinGW DLL. Коммерческой подписи издателя нет.

В среде Linux запуск Wine недоступен из-за ограничения IPC. Это не выдаётся за проверку окна или SCM.

## Windows CI

Workflow `.github/workflows/windows.yml` использует Windows Server 2022, MSBuild v143 со статическим CRT и Go 1.26.11. Действия закреплены по конкретным commit SHA.

Интеграционный стенд запускается только при явной тестовой переменной, на GitHub-hosted Windows runner с повышенным токеном и при отсутствии прежней службы/данных `ProxyServer21`. Он использует свободные loopback-порты, тестовые пароли и `manageFirewall=false`. Существующую VDS он не подключает.

В сценарии предусмотрены:

- защищённые каталоги, зашифрованный профиль и установка остановленной службы;
- старт SCM без GUI и чтение профиля через проверенный локальный IPC;
- независимое сохранение параметров обычного прокси и MTProto;
- реальные SOCKS5 username/password, отказ анонимного подключения, HTTP 407/200 и сохранность данных;
- открытие и выход из настоящего GUI с продолжающим работать GOST;
- аварийное завершение только подтверждённого дочернего GOST этого стенда и восстановление;
- отмена отложенного восстановления командой «Стоп»;
- новый процесс службы с сохранённым профилем и автозапуском;
- удаление службы, освобождение процессов/портов и сохранение профиля.

Наличие workflow означает наличие воспроизводимого теста. Успешное исполнение подтверждает зелёный результат конкретного запуска Actions и строка `WINDOWS_SERVICE_INTEGRATION_PASSED` в его журнале. Реальные logoff/перезагрузка Windows 10, внешняя доступность VDS и работа Telegram из конкретной сети проверяются отдельно.

## Приёмка на VDS

После установки проверьте подключение с телефона, затем закройте окно и повторите проверку. После этого отдельно проверяйте выход из Windows и перезагрузку. Сохраните рабочую копию 2.0 до завершения этих шагов. Перенос и возврат описаны в [SERVICE.md](SERVICE.md).
