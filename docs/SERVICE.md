# Служба Windows · Proxy Server 2.1

Служба запускает GOST и MTProto в фоне, до входа пользователя в Windows. Окно Proxy Server служит панелью управления: его можно закрыть, отключить RDP или выйти из учётной записи. Сетевые процессы при этом принадлежат службе.

## Переход с работающей версии 2.0

1. Сохраните настройки обычного прокси и страницы Telegram в старой программе. Сделайте резервную копию всей её папки, включая `proxy.ini` и сертификаты.
2. Распакуйте полный архив 2.1 в отдельную папку. Скопируйте туда **свой** `proxy.ini`, рядом с новым `ProxyServer.exe`. В релизе нет общего пароля или готового пользовательского INI.
3. Выполните переход под той же учётной записью Windows, которая сохранила настройки 2.0: её DPAPI используется при чтении старых паролей. Одного копирования INI на другую VDS или под другую учётную запись для восстановления секретов недостаточно.
4. Закройте старую программу через «Выход», чтобы освободить её порты. Это короткий перерыв в работе прокси. Обычное сворачивание в трей не освобождает порты.
5. Запустите новый `ProxyServer.exe`. Подтвердите штатный запрос Windows на права администратора. Проверьте логин, порты и существующий секрет Telegram. Для переноса рабочего Telegram новый секрет создавать не нужно.
6. На странице **«Служба»** выберите запуск обычного прокси и MTProto при старте службы. Для уже настроенных компонентов предлагается автоматический старт. Оставьте включённым разрешение выбранных портов службы в брандмауэре, если хотите, чтобы программа подготовила эти разрешения.
7. Нажмите установку службы и проверьте показанный список изменений. Установщик подготовит отдельную защищённую копию программы, компонентов и конфигурации. Служба получит автоматический запуск Windows.
8. Дождитесь состояния службы «Работает» и состояния нужных сетевых компонентов. Проверьте Telegram и браузер **с другого устройства**. Сначала закройте окно и повторите эту проверку, затем при необходимости проверяйте выход из Windows и перезагрузку.

Если в версии 2.1 до установки уже работали локальные компоненты, подготовка службы выполняется до их остановки. После успешной установки окно освобождает свои процессы и передаёт запуск службе. Другая, отдельно запущенная копия 2.0 автоматически не завершается: её нужно закрыть самостоятельно.

## Кнопки и настройки

| Действие | Результат |
|---|---|
| Установить службу | Создаёт защищённую установку и автоматическую службу, переносит введённые настройки |
| Запустить службу | Запускает службу; компоненты стартуют согласно своим флажкам автозапуска |
| Остановить службу | Останавливает GOST, MTProto и текущие соединения |
| Удалить службу | Останавливает службу и удаляет её регистрацию; защищённые данные остаются для восстановления |
| Старт / стоп обычного прокси | Управляет GOST внутри службы, когда она установлена |
| Старт / стоп Telegram | Отдельно управляет MTProto внутри службы |
| Закрыть окно / выйти из GUI | Завершает окно управления; установленная служба продолжает работу |
| Сохранить параметры | Записывает текущие параметры в профиль службы; редактирование работающего компонента ограничено |

Если служба установлена, окно получает настройки из её защищённого профиля. Старый `proxy.ini` в распакованной папке больше не является источником настроек службы. Обновление состояния и графиков не заменяет поля, которые вы редактируете.

Остановка отдельного компонента действует в текущем сеансе службы. Его флажок автозапуска определяет, будет ли он запущен при следующем старте службы или перезагрузке Windows. Чтобы оставить его выключенным и после перезагрузки, снимите этот флажок и сохраните соответствующую страницу.

Автозапуск окна через `HKCU\Run` для работы службы не требуется. Известная запись старой оболочки `PrivateProxyServer` отключается при успешной передаче управления; остальные записи автозапуска сохраняются. Повышенное окно может запрашивать UAC при ручном открытии.

## Учётная запись и хранение

Имя службы: **`ProxyServer21`**. Она работает от встроенной учётной записи **LocalSystem**. Пароль пользователя Windows при установке вводить не нужно. LocalSystem имеет высокие локальные права; запускайте только свою проверенную сборку и сохраняйте ограничения доступа к её каталогам.

| Что | Расположение |
|---|---|
| Программа службы и компоненты | `%ProgramFiles%\ProxyServer21\host-<идентификатор>\` |
| Профиль службы | `%ProgramData%\ProxyServer21\profile.dpapi` |
| Импортированные TLS-файлы | Защищённая папка данных службы |
| Старые настройки портативного режима | `proxy.ini` рядом с распакованным EXE |

Папки службы доступны SYSTEM и администраторам. Профиль зашифрован DPAPI с привязкой к этой Windows. Ограничения доступа к файлам обязательны: режим DPAPI для компьютера сам по себе не отделяет обычных пользователей друг от друга.

Установщик читает секреты 2.0 в контексте вошедшего пользователя и сохраняет профиль для службы заново. Он переносит существующие логин, пароль, пароль внешнего прокси и MTProto-секрет. Конфигурация GOST и mtg передаётся по закрытому stdin, без паролей в аргументах командной строки. Копии выбранных TLS-сертификата и ключа находятся в защищённых файлах, доступных службе при следующей загрузке.

Установка не принимает сетевые пути, символические ссылки и junction для собственных каталогов. Уже существующая папка с небезопасными разрешениями не присваивается автоматически. При такой ошибке сохраните её данные и выясните происхождение папки; не ослабляйте ACL для устранения ошибки.

## Брандмауэр при смене папки

Разрешение, выданное Windows старому `components\gost.exe`, может относиться только к его прежнему пути. Служба использует отдельную копию, поэтому ей нужны правила для нового расположения.

При выбранной опции установщик управляет только группой **`Proxy Server 2.1 - managed service`**. Правила одновременно ограничены путём соответствующего EXE и включёнными портами. Для GOST учитываются адрес прослушивания и разрешённый IP клиента; для MTProto используется его собственный адрес прослушивания. UDP разрешается только при включённом совместимом SOCKS-маршруте. Локальный DNS и внутренние метрики не получают публичных разрешений.

Программа сохраняет состояние профилей брандмауэра, RDP, системные правила и политику по умолчанию. При изменении параметров управляемые разрешения обновляются; сначала добавляется новый план, затем удаляются устаревшие собственные правила. Неудачная операция выполняет обратное восстановление и явно сообщает, если восстановление тоже не удалось.

Если опция выключена, подготовьте правила для новой папки вручную. Внешний сетевой экран провайдера и явные блокирующие правила Windows могут ограничивать доступ независимо от локальной установки. Состояние «Работает» подтверждает процессы и доступные локальные показатели, а проверка с телефона подтверждает внешний путь.

## Восстановление после сбоя

Служба наблюдает за принадлежащими ей процессами. При неожиданном завершении компонента запланированы повторные запуски с задержками **2, 5, 10, 30 и 60 секунд**. После исчерпания серии повторов требуется ручной запуск; это предотвращает непрерывный цикл ошибочных стартов. После 60 секунд устойчивой работы бюджет повторов восстанавливается.

Обычная команда «Стоп» не вызывает немедленного автоматического перезапуска компонента. В журнале и на странице службы показываются ошибки и число повторных запусков. Отдельно Windows применяет заданное восстановление самой службы при её аварийном завершении.

## Возврат к 2.0

1. Откройте 2.1 и остановите, затем удалите службу. Это освободит порты и отключит её следующий автоматический запуск.
2. Запустите сохранённую рабочую копию 2.0 с её исходным `proxy.ini` под прежней учётной записью Windows.
3. Проверьте подключения с клиента. Старые пользовательские правила брандмауэра не удалялись установщиком 2.1.

Удаление службы намеренно сохраняет защищённый профиль. Не публикуйте его, `proxy.ini`, TLS-ключи и собственные Telegram-ссылки в GitHub. В поставку исходников пользовательские настройки не включаются.

## Проверка конкретной сборки

Результаты сборки, автоматических проверок и ограничения стенда перечислены в [VERIFICATION.md](VERIFICATION.md). Кросс-компиляция Linux → Windows проверяет сборку и структуру EXE; исполнение SCM, DPAPI и Windows ACL подтверждается отдельным запуском на Windows. Фактический статус этих проверок указан отдельно, без подмены одним другим.

Технические основания: [SCM и StartServiceCtrlDispatcher](https://learn.microsoft.com/en-us/windows/win32/api/winsvc/nf-winsvc-startservicectrldispatcherw), [LocalSystem](https://learn.microsoft.com/en-us/windows/win32/services/localsystem-account), [DPAPI](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata), [правила по программе и портам](https://learn.microsoft.com/en-us/windows/security/operating-system-security/network-security/windows-firewall/rules).
