# Telegram: MTProto и SOCKS5

## Встроенный MTProto

1. Откройте страницу **Telegram**.
2. В поле публичного адреса укажите внешний IP или домен вашего VDS. Он нужен для ссылки подключения; программа не получает его через сторонний сайт автоматически.
3. Выберите свободный TCP-порт, по умолчанию 443. Если этот порт занят веб-сервером или другой службой, используйте свободный.
4. Укажите домен Fake TLS и создайте секрет. Значение `www.microsoft.com` — исходный пример, а не результат проверки доступности с вашего VDS. Подходит доступный HTTPS-узел с TLS 1.3; никакой сертификат или ключ этого узла вам не нужен.
5. Сохраните и запустите MTProto. Разрешите `components\mtg.exe` в брандмауэре для активного профиля и выбранного порта.
6. Скопируйте ссылку и откройте её в собственном Telegram. Ссылка содержит секрет — отправлять её следует только тем, кому хотите дать доступ к прокси.

Секрет начинается с `ee` и содержит случайный ключ и кодированное имя Fake TLS. Он защищён DPAPI при сохранении. Кнопка показа секрета и копирование ссылки доступны явно; обычные журналы его не содержат. При смене секрета обновите настройки клиентов.

Состояние «процесс работает» показывает запуск mtg, а не успешное соединение с Telegram. Необязательные диагностические обращения mtg к сервисам определения публичного IP отключены нашей CLI-правкой; работа протокола, защита от повторного воспроизведения и TLS-маскировка сохранены.

## Чем отличается от SOCKS5 и HTTPS

MTProto предназначен для Telegram. Он понимает транспорт Telegram и использует секрет доступа. SOCKS5 передаёт соединения разных приложений, обычно с логином/паролем. HTTPS-прокси — HTTP-прокси с TLS-соединением до прокси; его нельзя заменить адресом MTProto в браузере.

Fake TLS маскирует транспорт MTProto под TLS-подобное соединение. Это не MITM: прокси не устанавливает поддельный корневой сертификат на телефон, не расшифровывает переписку и не меняет модель шифрования Telegram. Прокси не превращает обычный облачный чат Telegram в сквозной секретный чат.

## Когда нужен купленный upstream

В этой версии GUI MTProto выходит из VDS напрямую. Если VDS не может соединиться с Telegram, использование MTProto на входе само по себе не меняет исходящий маршрут.

Для маршрута через купленный адрес:

1. Настройте внешний SOCKS5 или HTTP CONNECT на странице **Цепочка**.
2. Включите отдельный SOCKS5-вход, например TCP 1081.
3. В Telegram выберите **SOCKS5** и укажите IP VDS, 1081, локальные логин и пароль Proxy Server.

Данные провайдера остаются в настройках цепочки; они не совпадают по назначению с локальным паролем. Прямой 1080 и chained 1081 можно сравнить независимо. Отсутствие соединения с одним видом прокси не доказывает, что обязательно заработает другой: важны маршрут, доступность адресов и ограничения сети.

## Звонки и другие приложения

MTProto Proxy не является VPN и не переносит произвольный UDP всех программ. Работа звонков зависит от конкретного Telegram-клиента, выбранного типа прокси и сети. Эта сборка не обещает, что включение MTProto автоматически проксирует голосовые/видеозвонки.

Документация: [Telegram proxy links](https://core.telegram.org/api/links#proxy-links), [mtg v2.3.0](https://github.com/9seconds/mtg/tree/v2.3.0).
