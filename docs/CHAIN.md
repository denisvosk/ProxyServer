# Отдельные порты через купленный прокси

В этой сборке один процесс GOST может обслуживать прямые и chained входы одновременно. Это позволяет сравнить маршруты с одного устройства.

| Вход | Маршрут |
|---|---|
| SOCKS5 1080 / HTTP 8080 | Клиент → VDS → назначение |
| SOCKS5 1081 / HTTP 8081 | Клиент → VDS → купленный upstream → назначение |
| TLS 8443 / 1443 | Прямой либо через тот же upstream, по отдельной галочке |
| MTProto 443 | Отдельный mtg → Telegram напрямую |

## Настройка

1. Задайте локального пользователя и пароль на странице «Настройки».
2. На странице «Цепочка» выберите **SOCKS5** или **HTTP CONNECT** по информации провайдера. Здесь поддерживается обычное TCP-соединение к upstream. HTTPS upstream с TLS, NTLM/Digest и несколько upstream в GUI не предусмотрены.
3. Укажите адрес без `socks5://` или `http://` и отдельный порт. Принимаются ASCII-домен или IPv4.
4. Введите логин и пароль провайдера. Если используется авторизация по IP, оставьте оба поля пустыми и разрешите внешний IP VDS в панели провайдера.
5. Включите нужный вход цепочки. Для Telegram достаточно SOCKS5 1081. Сохраните и запустите сервер.
6. На устройстве укажите **IP VDS**, порт **1081**, локальные логин/пароль с первой страницы. Не вводите пароль купленного прокси вместо локального.

## Поведение при отказе

В конфигурации один конкретный upstream. Если он недоступен или отклоняет доступ, запрос через chained порт завершается ошибкой. Автоматического перехода на прямой маршрут нет; это проверено несколькими повторными запросами после остановки upstream для обоих типов прокси.

Прямые порты независимы и продолжают выходить с VDS. Разрешения провайдера на CONNECT-порты и доступ к сервисам сохраняют силу: наша оболочка их не меняет.

## DNS и UDP

Если клиент передал доменное имя, chained вход сохраняет его для upstream. Имя самого upstream при необходимости разрешается на VDS. Если клиент уже передал адрес назначения, используется этот адрес.

SOCKS5-цепочка использует стандартный UDP ASSOCIATE (`relay: udp`), когда внешний SOCKS5 его поддерживает. HTTP CONNECT upstream UDP не поддерживает; при его выборе UDP на соответствующем SOCKS-входе отключён. Не происходит обхода через прямой UDP.

## Telegram

Чтобы сравнить прямой и купленный маршруты, создайте в Telegram два SOCKS5-подключения: IP VDS:1080 и IP VDS:1081 с одинаковой локальной учётной записью. MTProto на отдельной странице — ещё один вариант входа, но у него в этой оболочке прямой исходящий маршрут. Если серверу доступен только купленный выход, используйте chained SOCKS5.

## Скорость

Цепочка добавляет ещё один узел и соединение; она помогает изменить доступность/маршрут, но не гарантирует ускорения. Сравнивайте один и тот же ресурс и клиент, прямой и chained порт, одинаковое время. Учитывайте CPU VDS, загрузку канала, RTT, ограничения провайдера upstream и клиента. График в интерфейсе — фактический трафик ваших соединений, не автоматический тест скорости и не обещанная полоса.
